# GY для бизнеса — прототип лендинга

Кликабельный прототип корпоративного направления Generation Yoga.
Структура «Вариант В»: распутье + 3 самостоятельные под-страницы.

## Как открыть

**Живой сайт: https://corporate.generation.yoga/** — GitHub Pages, ветка `main`,
корень репозитория. Публикуется сам: `git push` → через минуту-две обновилось.
Отдельной команды деплоя нет, кнопки «выкатить» тоже — что в `main`, то и у
заказчика.

Домен подключён 13.08.2026: в reg.ru запись `corporate CNAME xenaja.github.io.`,
в корне репозитория файл `CNAME` — из него Pages берёт адрес при каждой сборке,
удалять нельзя. Сертификат Let's Encrypt GitHub выпускает и продлевает сам,
принудительный HTTPS включён. Старый адрес `xenaja.github.io/gy-corporate/`
теперь редиректит сюда же.

Основной сайт generation.yoga живёт на Тильде и с этим репозиторием никак не
связан: у поддомена своя DNS-запись, общего сервера нет.

Локально — просто откройте `index.html` в браузере, всё работает.
Для проверки форм и трекинга лучше запустить локальный сервер (иначе часть JS
браузер ограничивает на `file://`):

```
cd site
python -m http.server 8080
# затем открыть http://localhost:8080
```

**Ссылки внутри — относительные** (`../assets/…`, `../pr/`), не от корня. Это
осознанно: сайт одинаково работает и на превью `xenaja.github.io/gy-corporate/`,
и в корне своего домена. С путями от корня (`/assets/…`) превью сломалось бы —
браузер искал бы файлы в корне `xenaja.github.io`.

Для рассылок дайте прямую ссылку на нужную под-страницу (агентствам — `/agency`).

## Техтеги, индексация, соцсети

- `canonical` и OG-разметка — на всех пяти страницах, адреса абсолютные
  (`https://corporate.generation.yoga/…`). Сменится домен — править здесь.
- Превью для мессенджеров: `assets/og/og-*.jpg`, 1200×630 — кадр героя
  страницы, затемнение к низу, логотип в углу. Меняете герой — пересоберите
  и og-картинку, иначе в телеграме будет висеть старая.
- `sitemap.xml` (пять адресов) и `robots.txt` с ссылкой на него.
- `404.html` вместо страницы GitHub. Пути внутри — от корня (`/assets/…`),
  потому что Pages отдаёт её по любому несуществующему адресу, включая
  вложенный: относительный путь оттуда не разрешится.
- Метрики и Вебмастера нет — ждём решения.

## Мобильная вёрстка — что проверено

Скриптом на ширинах 360, 390, 601, 700, 900 и 1100: горизонтального
переполнения нет ни на одной странице, оранжевая кнопка героя видна на первом
экране даже на 375×667.

Надзаголовок в герое /pr стоял на светлом кадре стеклянной кровли — контраст
2:1 при норме 4.5. Усилили вуаль на ширинах до 900px: стало 4.6:1, кадр при
этом не превратился в ровную заливку.

Акценты Fraunces не рвутся переносом только **от 601px**. Ниже строка короче
самого акцента, и `nowrap` выдавливал заголовок за экран — проверено на /pr,
где «у организаторов» уезжало на 36px. Перенос внутри акцента там меньшее зло,
чем обрезанный текст.

Герои отдаются через `srcset`: телефон берёт 900px-версию, десктоп полную.
На /pr это 178 КБ вместо 474 — снимок оранжереи детальный и в JPEG иначе не
жмётся. Файлы `*-900.jpg` — производные, руками их не правят.

Всё, кроме героев, грузится лениво (`loading="lazy" decoding="async"`).
Раньше отложены были только кадры на главной, и телефон при заходе на /hr
тянул 1,3 МБ картинок, хотя до первого экрана нужен один герой.

Мелочи под палец: `touch-action: manipulation` (снимает историческую задержку
300 мс на тапе), `-webkit-tap-highlight-color: transparent` (системная синяя
вспышка поверх оранжевой кнопки читалась как сбой), `env(safe-area-inset-bottom)`
в подвале — иначе последняя строка уезжает под индикатор айфона.

Меню на мобиле: кнопка 48×48 (было 42 — попадали не с первого раза), под
открытым меню страница затемняется и не прокручивается, закрывается тапом
по затемнению, клавишей Esc и выбором пункта.

## Заявки в Telegram

Кнопка «Связаться с менеджером» внизу главной открывает модальное окно
(нативный `<dialog>`, разметка в конце `index.html`). Отправка идёт не напрямую
в Telegram, а через воркер: токен бота нельзя класть в `site.js` — страница
статическая, токен увидели бы все.

Воркер уже развёрнут: `https://gy-lead-to-telegram.xenonline77.workers.dev`
(`cd worker && npx wrangler deploy` — пересобрать после правок).
`TG_CHAT_ID` задан — заявки идут в личку.

Осталось задать `TG_TOKEN` (токен бота от @BotFather):

```
cd worker && npx wrangler secret put TG_TOKEN
```

— и вписать адрес воркера в `LEAD_ENDPOINT` в `assets/js/site.js`.

Две грабли, обе уже стоили времени на «Кочевнике»: в личку бот пишет только
после того, как получатель нажал ему `/start`; хвостовой пробел в имени
переменной — воркер её не найдёт и будет молча отдавать `502`.

Проверить, не открывая сайт:

```
curl -X POST https://gy-lead-to-telegram.xenonline77.workers.dev \
  -H "Content-Type: application/json" \
  -d '{"form":"manager","name":"Тест","contact":"@nick","consent":"on"}'
```

`{"ok":true}` — заявка ушла в Telegram. `502` — не задан или неверен токен.

Пока `LEAD_ENDPOINT` пуст, форма ведёт себя как остальной прототип: показывает
экран «Заявка отправлена» с пометкой «демо-режим» и ничего не отправляет.
Как только адрес вписан, пометка со страницы уходит сама.

В форме уже стоят ловушка для ботов (скрытое поле `website` — заполненное
означает робота), обязательное согласие на обработку ПД и проброс UTM-меток.
`ALLOW_ORIGIN` в `worker/wrangler.toml` держать строго своим доменом, иначе
форму сможет дёргать чужой сайт.

Через воркер идут все шесть форм: заявки с `/hr`, `/pr`, `/agency`, оба
лид-магнита и модалка на главной. В Telegram каждая приходит со своим
заголовком (список — в `FORMS` в воркере), так что источник виден с первой
строки. Новая форма подключается атрибутом `data-lead="<имя>"` — и добавлением
имени в `FORMS`, иначе в заголовок попадёт технический id.

## Дизайн

Источник правды — `../gy-handoff/project/Визуальный стандарт GY.md` (эталон
вёрстки: `Главная - эталон.dc.html` там же). Кратко:

- Палитра: чернила `#0E0E0E`, бумага `#F6F1E8`, крем `#EFE7D6`, оранжевый
  бренда `#F26B1F`, второстепенный текст `#666`, волосяная линия
  `rgba(14,14,14,.12)`. Оранжевый — только акцент, никогда не заливка блока;
  один оранжевый фокус (кнопка) на экран.
- Шрифты: **Manrope 800 капсом** — все заголовки и кнопки; **Fraunces italic
  строчными** — одно-два акцентных слова в заголовке (разметка `<em>`).
  Подключены с Google Fonts — для офлайн/своего хостинга скачать локально.
- Сетка: контейнер 1160px, боковой padding 48px, вертикальный padding секции
  88px. Карточки белые, радиус 12, hairline-борд, min-height 260, фото-шапка
  170px, ссылка-действие прижата к низу.
- Ритм: база светлая, ink чередуется; **не более двух тёмных секций подряд**.
- Фото затемняются только придонным градиентом; цифры и подписи никогда не
  лежат поверх фото.

### Правило вёрстки

Вся вёрстка — в `assets/css/site.css`, всё поведение — в `assets/js/site.js`.
В страницах **не должно появляться ни `<style>`, ни `style="…"`**. Причина не
в эстетике: у инлайн-стиля специфичность выше любого селектора, поэтому он молча
перебивает и медиазапросы (адаптив ломается без единой ошибки в консоли), и
компонентные правила. Нужен разовый стиль — заводите класс:

- страничные компоненты (`.builder`, `.catalog`, `.terms`, `.wow`, `.policy`) —
  в секции «Страничные блоки» в конце `site.css`, обязательно со скоупом по
  классу страницы, иначе правило утечёт на соседние страницы;
- разовые отступы и кегли — в секции «Утилиты» (`.p-lg`, `.p-sm`, `.lede--wide`,
  `.form-head`, `.cta-row--split`, `.section-head--tight`).

Утилиты стоят **после** компонентов и у текстовых в селекторе есть элемент
(`p.p-sm`) — иначе `.p-sm` проигрывает `.card p` по специфичности и не работает.

### Один файл или несколько — по ситуации

Сейчас весь CSS в одном `site.css`, и это осознанный выбор под текущий размер, а
не догма. Пять страниц, страничных стилей ~70 строк, посетитель ходит
распутье → раздел → форма — при одном файле браузер скачивает CSS ровно раз и
дальше берёт из кэша. Плюс токены и компоненты лежат вместе, страничному файлу
негде разъехаться со стандартом.

**Разделить на `assets/css/pages/*.css` стоит, когда** появится хотя бы одно из:

- страниц становится заметно больше 5–7, и общий файл превращается в свалку;
- у отдельной страницы набирается своих 150–200+ строк (лендинг под кампанию,
  калькулятор, личный кабинет) — тогда остальным страницам незачем её возить;
- страницы начинают жить разными релизами или их правят разные люди — отдельный
  файл убирает конфликты в общем;
- появляется сборка, которая сама режет CSS по страницам, — тогда вопрос
  решается за нас.

Схема при разделении: `site.css` — токены, типографика, компоненты, утилиты
(подключается везде); `pages/hr.css` и т.д. — только то, что живёт на одной
странице, подключается вторым `<link>` после общего. На HTTP/2 (а Pages отдаёт
именно по нему) второй запрос стоит дёшево, так что дробить не страшно.

Чего делать не стоит в обоих случаях: возвращать `<style>` и `style=` в
разметку и тащить сборщик (PostCSS, Sass, бандлер) ради статики — Pages отдаёт
файлы как есть, а шаг сборки добавит звено, которое нечем окупить.
